## 1. What is `NPM`?

NPM is a package manager , it manages all the packages in our system. All the dependencies/packages in our system are managed by npm. In common ways we say NPM as Node Package Manager.

Our system will have one bundler and that bundler will depend on some packages those packages/dependencies will have their own dependencies this is called transitive dependency.

All the dependency and the transitive dependency in our project will be managed by NPM
Our project have parcel and parcel depend on some packages, parcel along with project have their own dependencies these are all managed by NPM

## 5.  What is difference between `dependencies` vs `devDependencies` ?

In our app we have 2 types of dependencies those are dependencies and devdependencies. devdependencies means we are installing it only on dev environment that is not needed in production environment , in devdependecies the code will be detailed way to better understand/ better develop to develoeper

dependencies will be installed on both dev and productions, these contains dependencies which we should need in both dev and prod. those dependencies will execute on both dev and prod. which contains optimized code aswell 

* devDependencies are tools needed only during development (like testing frameworks, linters, or bundlers like Parcel). Regular dependencies are packages required for the application to run in production (like React or Axios).

## 6.  What is Tree Shaking?

* Tree shaking is a feature of parcel. parcel bundler is giving to us . tree shaking means if we have 100 files in our app and we only using 10 files out of 100, the tree shaking means it will remove all the unsed code (dead code) from the final bundled production file. If you import only 1 function from a library of 100 functions, tree shaking ensures only that 1 function is included in the final bundle.

## 10.  What is the difference between `package.json` and `package-lock.json` ?

package.json is a configuration file for our NPM (NPM manages all our packages in our system), it contains all the dependencies our system contains. 

package-lock.json file keep a note of all the exact version of dependencies our system is using, and it also has something called as integrinty which contains hash which means are all the dependencies version installed in dev and prod same or not , this file will take care of it. it kind of locks all the versions of dependencies that are being installed on our system and also maintains a hash,

## 11. Why should I not modify `package-lock.json`?

we should not modify package-lock.json because this will interupt the version of the dependencies that have been installed, and also may cause issue at hashing ,  if we modify package-lock.json means it may not work properly in dev or in prod. Miss alignment may happen with actual installed versions of dependencies and versions present in modified package-lock.json file. this may result in app crashing in both dev and prod.

* modifying it breaks the reproducibility of the build. It ensures that every developer on the team and the production server install the exact same dependency tree down to the exact commit or version.
